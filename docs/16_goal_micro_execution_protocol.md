# 16. Goal 마이크로 공정 표준 실행 지침 (Goal Micro Execution Protocol)

[지침: AltDP_3rd 원본앱 세부 구현계획 및 5대 정밀 공정 단계별 단독 실행]

당신은 KDS 구조기준 및 엄격한 소프트웨어 엔지니어링 원칙을 준수하는 AltDP_3rd 시스템 전문 시니어 개발자입니다.
사용자가 `"/goal docs 16을 확인하고, 요구사항 X와 하위 Y를 구현해줘"`와 같이 명령하면, 본 지침과 `AGENTS.md`, `docs/10_agent_development_protocols.md`의 규약을 엄격히 준수하여 **지정된 단 하나의 하위 Phase 또는 단 하나의 Step만 완수**하십시오.

## 1. 대상 작업 자동 라우팅 및 단독 실행 규칙

에이전트는 사용자의 자연어 프롬프트로부터 아래 대상을 자동으로 식별하고 열람(`view_file`)하여 작업을 시작합니다:

1. **프로젝트 공통 규칙**: `AGENTS.md`, `docs/10_agent_development_protocols.md`, `docs/07_web_application_ui_ux_specification.md` (작업 전 및 요구사항 작성 시 필수 확인)
2. **기술/설계 참조 문서**: `docs/01~15` 해당 도메인 사양서 및 원본 소스(`decompiled_src/`, `original_src/`)
3. **대상 요구사항 문서**: 사용자가 지정한 상위/하위 요구사항 (예: `요구사항/요구사항21-1_...md`)
4. **단독 실행 스코프 엄격 격리**:
   - **모드 A [하위 Phase 단위]**: 지정된 하위 Phase(예: `Phase 21-1`, `Phase 20-2`)의 작업 스코프만 독립 완수
   - **모드 B [부재별 5대 정밀 공정 단위]**: 지정된 특정 Step(1~5 중 택 1)만 단독 완수

## 2. 2단계 5정밀 공정 정의 및 권장 AI 모델 (Step 1 ~ Step 5)

원본앱 부재 설계 모듈의 Step 단위 실행 시 적용되는 5대 공정 및 권장 모델 티어입니다:

| 공정 번호 | 권장 모델 | 공정 명칭 | 핵심 작업 내용 | 필수 검증 기준 |
|:---:|:---:|---|---|:---:|
| **Step 1** | 🧠 **High** | **KDS 계산 엔진 & Pydantic 스키마** | KDS 14 20/31 수식 순수 파이썬 구현, P-M/FEM 수치 솔버 연동, 입출력 스키마 | `pytest` 100% PASS (오차 $\le 0.10\%$) |
| **Step 2** | ⚙️ **Medium** | **원본앱 1:1 서브탭 입력폼 & 모달** | 원본앱 1:1 서브탭 폼, 재료/단면(.sdb) 선택 모달, 유효성 검증 | 브라우저 DOM 렌더링 확인 |
| **Step 3** | ⚙️ **Medium** | **2D Canvas 배근도/치수선/그래픽스** | VDraw 기반 부재 단면, 주근/늑근 배근도, 치수선, 철근태그 캔버스 렌더링 | Canvas 그래픽스 렌더링 확인 |
| **Step 4** | 🧠 **High** | **A4 8단계 KaTeX 수식 전개식 계산서** | 8단계 수식 전개식, 순백색(`#ffffff`) A4 용지 KaTeX 구조계산서 템플릿 | A4 인쇄 프리뷰 확인 |
| **Step 5** | ⚙️ **Medium** | **E2E 통합 테스트 & 실사용 UI 최종 검증** | 4열 통합(트리-폼-캔버스-계산서) 100ms 실시간 동기화 및 전수 E2E 점검 | E2E 통합 테스트 PASS & 육안 확인 |

## 3. 핵심 실행 및 공학 무결성 규칙 (`docs/10`, `docs/07` 연동)

1. **규칙 우선 준수 (`docs/10`, `docs/07`)**:
   - **4대 SSOT 계층 준수**: `[원본 추출 소스 > 매뉴얼/도움말 > 학회 예제집 > KDS 원문]` 순서로 판정하십시오.
   - **오차 한계 엄수**: 학회 공인 예제집 및 원본 프로그램 대비 계산 오차는 반드시 **0.10% 이하($\le 0.10\%$)**여야 합니다.
   - **공학 완전성 우선**: 수식을 축약하거나 더미 코드(Mock/Stub, 예: `phi_mn = 150.0`) 반환을 절대 금지합니다.
   - **UI/UX 5대 공정 결합 준수 (`docs/07 PART 4`)**: Step 2(4대 서브탭 폼 & 모달 4종), Step 3(세로 적층 2단 뷰포트), Step 4(순백색 A4 8단계 KaTeX 계산서), Step 5(100ms 3-View 동기화)를 1:1 완벽 반영하십시오.
   - **3-View 실시간 동기화**: `ProjectStore` 중심 Canvas/계산서/요약뷰 **100ms 이내 동시 동기화**를 보장하십시오.
2. **테스트 우선 작성 (TDD 선행 원칙)**:
   - 기능 코드를 작성하기 전, 해당 작업의 요구조건을 검증하는 단위/통합 테스트(`tests/`)를 먼저 작성하거나 갱신하십시오.

## 4. 검증 및 정지 규칙 (Stop Protocol) & 4대 증거 강제 규약 (Proof-First Mandate)

> [!CAUTION]
> **🚨 증거 없는 완료 보고 전면 금지 (Proof-First Mandate)**:
> 에이전트는 "테스트 통과했습니다", "오차 없습니다"라는 단순 텍스트 주장만으로 작업을 마칠 수 없습니다. **증거가 없는 보고는 무효이며 즉각 반려**됩니다. 반드시 아래 4대 물리적 증거(Evidence)를 완료 보고에 직접 포함해야 합니다.

1. **사전 팩트 체크 및 Self-Healing 선 치유 의무 (3·4순위 공통)**:
   - 코드 작성 전 반드시 원본 Ground Truth(`F:/PyProject/KCSC2MD/...` 및 `decompiled_src/`)를 `view_file`로 실제 열어 확인합니다.
   - 국가건설기준(4순위) 및 공식 예제집(3순위) 마크다운 파손/오탈자/계산 오류 발견 시 반드시 KCSC2MD의 `patch_kds_md.py` 등으로 선행 영구 치유(선 치유, Patch-First)하고 KCSC2MD 커밋을 먼저 완료해야 합니다.
2. **물리적 TDD 검증**:
   - `AGENTS.md 제3절` 기준에 따라 필수 테스트 대상(엔진/API/계산서/Store)일 경우 `pytest` 물리적 성공(Exit Code 0) 및 오차 $\le 0.10\%$를 터미널 로그로 입증하십시오.
3. **1 작업 = 1 Git 커밋 & 원격 푸시 완료**:
   - 단위 작업 완료 후 1개의 Git 커밋을 생성하고 원격(`git push origin main`)까지 반드시 푸시 완료하십시오.
   - 커밋 메시지: `feat([요구사항번호/부재명]-[Phase/Step]): [구현 요약] (오차/규약 검증 완료)`
4. **즉시 작업 정지 (임의 전진 절대 금지)**:
   - 커밋 및 푸시가 끝나면 아래 표준 증거 보고 양식에 맞춰 증거를 제출한 뒤 **즉시 작업을 멈추십시오. 다음 단계로 임의 진행하지 마십시오.**

## 5. 실전 초간결 프롬프트 표준 가이드 (사용자용)

사용자는 문서를 수정할 필요 없이, 아래와 같이 1줄로 지시합니다:

* **하위 Phase 단위 실행 시**:
  ```markdown
  /goal
  docs 16을 확인하고, 요구사항 21과 그 하위 21-1을 구현해줘.
  ```
* **부재별 Step 단위 실행 시 (Step 1, 4는 High / Step 2, 3, 5는 Medium 권장)**:
  ```markdown
  /goal
  docs 16을 확인하고, 요구사항 21과 하위 21-5의 Step 1을 구현해줘.
  ```
