## 2. 세부 개발 사양 (Detailed Specifications)

### 2.1. 부재별 다형적 플러그인 번들 구조 (`src/web/static/js/modules/`)
* **디렉토리 및 모듈 팩 구조**:
  ```
  src/web/static/js/modules/
  ├── rc_beam/                   # RC 보 전용 팩 (4대 서브탭, 세로2단 캔버스, 휨/전단/처짐 계산서)
  ├── rc_column/                 # RC 기둥 전용 팩 (4대 서브탭, 단면+P-M 캔버스, P-M 계산서)
  ├── rc_footing/                # RC 기초 전용 팩 (4대 서브탭, 평면+접지압 캔버스, 지내력 계산서)
  ├── steel_beam/                # 철골 보 전용 팩 (Section DB 서브탭, 단면+LTB 캔버스, 횡좌굴 계산서)
  └── steel_baseplate/           # 베이스플레이트 전용 팩 (앵커 서브탭, CAD상세+파괴면 캔버스, 지압 계산서)
  ```
* **모듈 인터페이스 규약 (Module Pack Protocol)**:
  각 모듈 번들은 아래 표준 인터페이스를 반드시 구현해야 합니다:
  ```javascript
  export interface ModulePack {
    id: string;                      // 예: "rc_beam"
    name: string;                    // 예: "RC 보 (Beam)"
    getDefaultData(): object;        // 기본 부재 제원 반환
    renderForm(container, data, bus): void;     // Pane 2 입력폼 렌더링
    renderGraphics(geomCanvas, mechCanvas, data, result): void; // Pane 3 상/하단 그래픽 렌더링
    renderReport(container, data, result, options): void;       // Pane 4 KaTeX 계산서 렌더링
    calculate(data): Promise<object>;// 백엔드 KDS 엔진 API 호출
  }
  ```

### 2.2. 모듈 디스패처 (`dispatcher.js`) & 100ms 동기화 버스 (`event_bus.js`)
* **대상 파일**: `src/web/static/js/core/dispatcher.js`, `src/web/static/js/core/event_bus.js`, `src/web/static/js/store/project_store.js`
* **동작 명세**:
  1. **고속 모듈 스위칭 (Switch Time < 50ms)**: 사용자가 사이드바에서 다른 모듈(예: RC보 $\rightarrow$ RC기둥)을 선택하면, `ModuleDispatcher`가 기존 DOM을 안전하게 언마운트하고 신규 모듈 팩의 4-Pane을 50ms 이내에 즉각 로드.
  2. **100ms 실시간 동기화 파이프라인**:
     - 사용자가 폼 수치를 변경하거나 `[💾 적용]` 클릭 시:
       `form_generator` $\rightarrow$ `ProjectStore.updateMember()` $\rightarrow$ `EventBus.emit('MEMBER_UPDATED')` $\rightarrow$ Pane 3 캔버스 재드로우 + Pane 4 계산서 재계산 + Pane 1/사이드바 DCR 글자 갱신.
     - 전체 파이프라인 지연 시간 $\le 100\text{ms}$ 보장.

### 2.3. 5대 플래그십 부재 4-Pane 수직관통 E2E 검증
1. **RC 보 (`rc_beam`)**: 직사각형/T형 보 단면, 상/하 2단 배근, 휨/전단/처짐/균열 안전성 검토.
2. **RC 기둥 (`rc_column`)**: 직사각형/원형 단면, 축력-휨 3D P-M 상관곡선, 장주효과 검토.
3. **RC 기초 (`rc_footing`)**: 독립기초판 평면 배근, 편심 접지압 분포, 1/2방향 뚫림전단 검토.
4. **철골 보 (`steel_beam`)**: KS H형강 Section DB 연동, 판폭두께비, LTB 횡좌굴 휨내력 검토.
5. **철골 주각부 (`steel_baseplate`)**: 베이스플레이트 지압, 앵커볼트 인장/전단 파열면 검토.

### 2.4. 엔지니어링 오차 무결성 ($\le 0.10\%$) 및 콘솔 에러 0건
* 5대 플래그십 부재의 KDS 엔진 계산 결과가 학회 예제집 및 원본앱 대비 **오차 0.10% 이하**여야 함.
* 브라우저 개발자 도구 콘솔에 빨간색 런타임 예외 에러(Exception)가 **0건**이어야 함.

## 3. 세부 작업 5단계 공정 (Step 1 ~ Step 5)
* **Step 1: 다형적 모듈 팩 인터페이스 및 디스패처 구현 (`dispatcher.js`)**
  - 모듈 등록, 동적 번들 임포트, 4-Pane 동시 스위칭 엔진 구현.
* **Step 2: 5대 플래그십 모듈 번들 패키징 (`src/web/static/js/modules/`)**
  - RC보, RC기둥, 기초, 철골보, 주각부 5종 번들화 및 폼/캔버스/계산서 브릿지 연결.
* **Step 3: ProjectStore & EventBus 100ms 실시간 동기화 확립**
  - 데이터 변경 이벤트 발행/수신 및 4-Pane 즉시 반응 파이프라인 연동.
* **Step 4: 브라우저 콘솔 에러 0건 전수 검수창구 확립**
  - 5개 모듈 상호 전환 및 데이터 조작 시 자바스크립트 콘솔 에러 0건 확인.
* **Step 5: 3자 삼각대조 오차 검증 및 Git 커밋**
  - 5대 부재 계산 결과 학회 예제집 대조(오차 $\le 0.10\%$) 검증 후 커밋/푸시.

## 4. 수용 기준 및 1:1 체크리스트 (Acceptance Criteria)
- [ ] 모듈 디스패처가 5대 부재 모듈 간 전환을 50ms 이내에 깜빡임 없이 매끄럽게 수행하는가?
- [ ] 입력폼 값 변경 및 적용 시 2D 그래픽, 계산서, 부재 목록이 100ms 이내에 동시 갱신되는가?
- [ ] 5대 플래그십 부재(RC보, 기둥, 기초, 철골보, 주각부)가 4-Pane 워크스페이스에서 100% 정상 작동하는가?
- [ ] 브라우저 콘솔 창에 런타임 에러나 Uncaught Promise Rejection이 단 1건도 없는가?
- [ ] 공인 예제집 및 원본앱 대비 계산 오차가 전수 0.10% 이하($\le 0.10\%$)를 만족하는가?
