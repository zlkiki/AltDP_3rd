# 요구사항 20: Midas Design+ 원본 UI·그래픽·입력·계산서 1:1 완벽 이식 및 4열 웹 프레임워크 명세서

## 1. 개요 및 목적 (Vision & Objectives)

본 요구사항은 Midas Design+(`Design+.exe`, `Language/Korean/`, `DgnLanguage/Korean/`, `decompiled_src/`)의 **엔지니어링 인터페이스 및 출력 시스템**을 현재 완성도 높은 웹앱의 **상단 글로벌 헤더 + 4열 레이아웃(트리메뉴 - 그래픽캔버스 - 사용자입력 - 구조계산서)** 컨셉 위에 100% 원본 그대로 정밀 이식하는 것을 목적으로 합니다.

### 핵심 준수 원칙
1. **트리메뉴 원본 체계 100% 준수**: 모듈의 순서, 배치, 탭 분류(콘크리트, 철골, 합성부재, 알루미늄, 보강, 기초 등)를 원본 `Menu.ini` 및 WorkTree 구조와 동일하게 구축.
2. **그래픽표시부 원본 드로잉(VDraw) 100% 준수**: 원본 `CODABeamBase`, `CODABaseColumn`, `CODABaseFooting`, `CODABaseSteel` 드로잉 엔진의 외곽선, 음영 해치, 피복 옵셋, 135도 스터럽 갈고리 절곡, 주철근 솔리드 원형, 치수선, 철근 태그 지시선, P-M 다이어그램 렌더링 방식을 브라우저 캔버스/SVG로 1:1 재현.
3. **사용자 정보 입력부 및 대화창(Dialog) 100% 준수**: 원본 다이얼로그(`DLG_*.ini`)의 모든 입력 파라미터, 내부 탭 구조 및 버튼 클릭(`...`) 시 발생하는 서브 대화창(모달 팝업) 체계를 웹 모달로 완벽 구현.
4. **구조계산서 원본 포맷 100% 준수**: 원본 `GENDgnReportKR.ini`, `DgnReportBase.ini`의 5대 장구분(일반사항, 재질 및 단면, 설계하중, 단면검토, 종합판정), 단면도/P-M 그림 삽입, `  →  O.K` / `  →  N.G` 판정 화살표 표기 및 보고서 모드를 그대로 계승.
5. **부재별 동적 디스패처 및 플러그인 아키텍처**: 각 설계모듈마다 완전히 달라지는 입력 폼, 캔버스 드로잉, 계산서 수식을 독립된 모듈 팩으로 패키징하고, 트리메뉴 선택 시 2열·3열·4열이 유기적으로 동시 스위칭되는 디스패처 구조 확립.
6. **P/S/M 모드 구분 보류**: 현재 구분이 명확하지 않은 P(설계)/S(검토)/M(일괄) 모드 분기는 보류하고, 단일 통합 "파라메트릭 입력 & 실시간 검토" 워크플로우로 단일화.
7. **기존 4열 웹 레이아웃 미학 유지**: 시각적 가독성과 작업 효율성이 검증된 4열 레이아웃 및 상단 글로벌 툴바의 모던 프리미엄 다크/글래스모피즘 컨셉을 그대로 유지.

## 3. 부재별 동적 디스패처 및 플러그인 아키텍처 (Dynamic Module Dispatcher)

부재(설계모듈)마다 입력 폼 항목, 서브 대화창, 2D/3D 드로잉 기하 알고리즘, 구조계산서 수식이 완전히 상이하므로, 중앙 집중식 모놀리식을 지양하고 **"부재별 독립 플러그인 모듈 & 동적 디스패처 패턴 (Module Registry & Dispatcher Pattern)"**을 적용합니다.

### 3.1. 동적 모듈 스위칭 라이프사이클 흐름도

사용자가 1열 트리메뉴에서 부재를 선택하면, `ModuleDispatcher`가 활성 부재의 메타데이터를 기반으로 **2열(그래픽), 3열(입력폼), 4열(계산서)**의 전용 컴포넌트를 즉각 교체 및 동기화합니다.

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 트리 메뉴에서 부재 클릭: [RC 보 1F-B1] ────────► [RC 기둥 1F-C1]                                            │
└──────────────────────────────────────┬──────────────────────────────────────────────────────────────────────┘
                                       │
                                       ▼ ModuleDispatcher.switchModule('rc_column', memberId)
 ┌─────────────────────────────────────┼────────────────────────────────────────────────────────────────────┐
 │                                     │                                                                    │
 ▼                                     ▼                                                                    ▼
[2열: 그래픽 캔버스 스위칭]             [3열: 사용자 입력 패널 스위칭]                                         [4열: 계산서 뷰어 스위칭]
• 기존: 보 단면(스터럽+늑근) 언마운트   • 기존: 보 탭(보폭/유효폭/처짐) 언마운트                               • 기존: 보 휨/전단/균열식 언마운트
• 활성: 기둥 캔버스 마운트             • 활성: 기둥 4대 탭 마운트                                            • 활성: 기둥 5대 장구분 마운트
  - CODABaseColumn 기하 렌더러          - [단면/재료]: cx, cy, 사각/원형 선택                                 - 1장: 일반조건
  - 주철근 원형/사각 루프 배열          - [철근배근]: 주철근 외곽/중간 배치                                   - 2장: 기둥 단면성질 + 단면도
  - P-M 상관곡선 차트 뷰포트            - [설계하중]: Pu, Mux, Muy 이축휨 하중                                 - 3장: 축력/이축휨 하중조합
  - 축력-이축모멘트 3D 곡면 뷰          - [옵션]: 장주효과(El, kL/r), 내진연성                                 - 4장: P-M 상관도 판정식 + 차트
• 서브 대화창 연결:                    • 서브 대화창(모달) 바인딩:                                            - 5장: Pu/φPn, Mu/φMn  →  O.K
  (단면 확대, 응력 등고선)               (IDD_RCS_COLUMN_PMODE_DLG, 기둥단면 상세, 하중조합)
```

### 3.3. 모듈별 표준 인터페이스 규약 (Module Interface Contract)

모든 설계 모듈은 `BaseMemberModule` 표준 인터페이스를 상속/구현하여 프레임워크와의 완벽한 결합도 분리를 유지합니다:

```javascript
class BaseMemberModule {
    // 1. 3열 입력부: 해당 부재의 4대 서브 탭 및 파라메트릭 폼 DOM 생성
    renderForm(container, currentData, onChangeCallback) {}

    // 2. 3열 입력부: '...' 클릭 시 호출되는 원본 서브 대화창(모달) 팝업 처리
    openSubDialog(dialogId, currentData, onApplyCallback) {}

    // 3. 2열 그래픽부: VDraw 원본 알고리즘에 따른 2D 단면/상세 드로잉
    renderCanvas(canvasCtx, currentData, analysisResult, viewOptions) {}

    // 4. 4열 계산서부: 원본 5대 장구분에 따른 KDS 수식 및 그래픽 임베딩 리포트 생성
    renderReport(reportContainer, currentData, analysisResult, reportMode) {}
}
```

### 3.4. 부재별 3대 영역(입력부·그래픽부·계산서부) 차별화 매핑

| 설계 모듈 | 2열 그래픽 표시부 (VDraw) | 3열 사용자 입력부 & 서브 대화창 | 4열 구조계산서 (5대 장구분) |
|---|---|---|---|
| **RC 보 (Beam)** | • 콘크리트 외곽선 + 135° 후크 스터럽<br>• 상/하부 다단 주철근 + 지시선 태그 | • 탭: [단면/재료] [배근] [하중] [옵션]<br>• 모달: T형 플랜지 유효폭, 처짐/균열 상세 | • 휨모멘트($\phi M_n$), 전단력($\phi V_n$)<br>• 장단기 처짐, 직접 균열폭 판정 |
