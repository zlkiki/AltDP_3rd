## 2. 세부 개발 사양 (Detailed Specifications)

### 2.1. `docs/07` 독립 4-Pane 상호작용 무결성 검증
* **검증 대상 4대 영역**:
  - `[Left Sidebar]` (설계 모듈 탐색기: 카테고리 필스, 트리 레벨 1~3, 고정핀)
  - `[Left-Sub]` (`pane-member-list` 부재 관리 + `pane-input-form` 사용자 입력부)
  - `[Center]` (`pane-graphic-view` 2D VDraw 단면/배근도 캔버스)
  - `[Right]` (`pane-right-report` KDS 구조계산서 상시 순백색 `#ffffff` A4 시트)
* **동작 요건**:
  - 모듈 전환 시 100ms 이내에 Left-Sub, Center, Right가 동시에 반응하여 깜빡임이나 이전 부재 데이터 잔존 없이 매끄럽게 스위칭되어야 함.

### 2.2. 브라우저 콘솔 무결성 (Zero-Exception Guarantee)
* 웹 서버 구동(`http://localhost:8000`) 후 개발자 도구(F12) 콘솔 검증:
  1. `404 Not Found` 정적 에셋(JS, CSS, 폰트, 이미지) 에러: **0건**.
  2. `Uncaught TypeError` / `ReferenceError`: **0건**.
  3. `Promise Rejection`: **0건**.

### 2.3. 플래그십 부재 vs WIP 부재 이중 검증 (`docs/12`, `docs/14`)
* **플래그십 부재 (`rc_beam` 등)**:
  - 폼 입력 변경 시 $\rightarrow$ 2D 배근도 실시간 재렌더링 $\leftrightarrow$ KDS 휨/전단/처짐 재계산 및 5대 장구분 계산서 즉시 갱신 확인.
* **WIP 부재 (지하외벽, 옹벽, 가새 등)**:
  - Left-Sub Midas WIP 카드, Center 2D VDraw WIP 캔버스, Right 순백색 A4 5대 장구분 WIP 시트가 정확한 티어(Tier 1/2/3) 뱃지와 함께 노출 확인.
  - **레거시 4-Pillar 카드 뷰(`redcr_common_renderer.js`)가 단 1건도 노출되지 않고, 순백색 A4 WIP 시트로 단일화되었음을 전수 확인**.

## 3. 세부 작업 5단계 공정 (Step 1 ~ Step 5)

1. **Step 1 [Medium]**: `index.html` 내 등록된 스크립트 및 모듈 임포트 경로 전수 점검 (누락 파일 차단).
2. **Step 2 [Medium]**: `app.js` 및 `dispatcher.js` 내 예외 처리 방어 로직(Try-Catch 및 안전한 DOM 가드) 보강.
3. **Step 3 [High]**: 61종 전 부재 순회 클릭 자동화 E2E 스크립트(`tests/ui/test_wip_baseline_e2e.py`) 작성 및 실행.
4. **Step 4 [Medium]**: 백엔드 전체 테스트 스위트(`pytest`) 실행 및 100% PASS 확인.
5. **Step 5 [High]**: 실제 브라우저에서 서버 가동 후 F12 콘솔 에러 0건 및 4-Pane 동기화 육안 최종 확인.

## 4. 완료 검증 기준 (Acceptance Criteria)
* 61종 모듈 트리를 임의 순서로 고속 클릭하여도 브라우저 콘솔에 에러 로그가 단 1건도 찍히지 않을 것.
* 플래그십 부재의 KDS 계산 및 동기화가 정상 작동할 것.
* WIP 부재 선택 시 `redcr_common_renderer.js`의 카드 뷰가 일절 노출되지 않고, 순백색 `#ffffff` A4 5대 장구분 WIP 시트가 정확히 렌더링될 것.
* 전체 pytest 스위트가 에러 없이 100% 통과(Exit Code 0)할 것.
